# Reproducibility Notes

This document explains how to reproduce the public computational results and how the repository separates source inputs, validated reference results, and locally generated outputs.

## 1. Reproducibility status

The public scripts were derived from the final controlled-validation scripts after the empirical specifications were frozen.

Public-code changes were limited to reproducibility and repository hygiene, including:

- relative paths;
- public output names;
- removal of machine-specific absolute paths;
- module documentation;
- preservation of validation guardrails.

The public versions were executed against the repository-formatted inputs and checked against the frozen reference analyses.

## 2. Repository root

All scripts should be run with the working directory set to the repository root:

```text
hydropower-climate-risk-brazil/
```

Do not run the scripts from inside an individual `code/` subfolder unless you explicitly reset the working directory to the repository root.

A quick R check is:

```r
getwd()
file.exists("README.md")
file.exists("code")
file.exists("data")
file.exists("results")
```

## 4. Package-version policy

The repository does not currently include an `renv.lock` file and therefore does not hard-pin all package versions.

This is an important reproducibility limitation: future package API changes can potentially affect execution even when data and scripts are unchanged.

The scripts generate or report execution metadata where applicable, including `sessionInfo()` files in local `outputs/` directories.

For archival-grade replication, users should retain the generated session-information files together with the commit hash used for the run.

## 5. Random seed

The physical ARDL scripts set:

```r
set.seed(123)
```

The main estimation routines are deterministic for a fixed R/package environment and fixed inputs; the seed is retained as an additional reproducibility safeguard.

## 6. Output policy

Locally generated files are written under:

```text
outputs/
```

This directory is ignored by Git.

The repository separately contains frozen validated public reference workbooks under:

```text
results/
```

This distinction is intentional:

- `outputs/` = files generated by the current local run;
- `results/` = validated reference outputs committed to the repository.

## 8. Important note on the Module 01 → Module 03 link

Module 03 reads the **validated reference outputs** in `results/01_monthlyization/`, not the files just created in `outputs/01_monthlyization/`.

This is deliberate in the validated public pipeline.

It separates two checks:

1. whether Module 01 reproduces its validated reference results;
2. whether Module 03 reproduces the financial results using the validated monthlyized inputs.

A user who wants to test a fully chained alternative using newly generated Module 01 files should do so only after first confirming that those workbooks are equivalent to the reference results. Any change to Module 03 input paths should be documented as a local reproducibility experiment rather than treated as the frozen public specification.


These values are convenient high-level checks; the committed result workbooks remain the authoritative public reference outputs.

## 11. Workbook metadata and checksums

Spreadsheet files (`.xlsx`) are ZIP/XML containers. Re-saving an otherwise logically identical workbook can alter internal metadata, ZIP ordering, or compression and therefore change a whole-file MD5 checksum.

For that reason:

- checksums identify a specific binary file;
- a different checksum does not, by itself, establish that analytical cell values changed;
- workbook-equivalence checks should inspect analytical sheets and values in addition to file hashes.

The committed public input files should nevertheless be treated as the canonical binary inputs for reproducing the repository version.

## 12. Language and variable names

Public explanatory documentation is in English.

Some internal:

- worksheet names;
- analytical variable names;
- output column names;
- legacy console messages

remain in Portuguese because they are part of the validated computational objects.

They were intentionally not renamed after validation to avoid introducing avoidable differences into the analytical pipeline.

## 13. Files that are intentionally not part of the public repository

Internal controlled-validation materials are not needed for normal reproduction and should remain outside the public repository, including:

- historical or superseded script versions;
- focused audit scripts;
- golden RDS objects;
- internal comparison workbooks;
- validation logs;
- local `runner.log` files;
- locally generated `sessionInfo` files;
- diagnostic DOCX files generated during local runs.

These materials may be retained privately for audit traceability.

## 14. Git hygiene

The `.gitignore` should exclude at least:

```gitignore
outputs/
.Rproj.user/
.Rhistory
.RData
.Ruserdata
*.Rproj
```

Before committing, useful checks are:

```r
system("git status --short")
system("git diff --cached --name-status")
```

No files under `outputs/` should appear in the commit.

## 15. Reproduction boundary

The repository is designed to reproduce the empirical results from the committed analysis-ready data.

It does not currently provide a complete automated pipeline from original institutional provider downloads through every upstream cleaning, imputation, and X-13 transformation step for the physical ARDL data.

Accordingly, the appropriate claim is:

> **The repository reproduces the reported estimation, diagnostics, stress tests, temporal disaggregation, financial transmission, and RaR10 results from the committed analysis-ready inputs.**

It should not be described as a one-command reconstruction of all source data from the original providers.
